# リアルタイム敵行動選択設計（承認済み草案）

更新: 2026-08-23  
状態: パイロット実装と6遭遇×1000 seedの60秒分布計測まで完了。手動実戦計測前  
対象: 個別行動、長期行動パターン、HP・フェーズ・クールダウンによる次パターン選択

## 1. この設計で決めること

リアルタイム戦闘の敵行動を次の四層へ分ける。

```text
敵固有コマンド
  通常攻撃、連撃、防御、ジャンプ反応、踏ん張り反応の実行内容と値
        ＋  種類で結合
共有タイミングカタログ
  A / C / G / J / Bの順序、実行秒、予告、連撃間隔、休止
        ↓  各敵が原則5～6個を装備し、全体速度倍率を一度だけ適用
敵ごとの行動セット
  固有コマンド、共有タイミング、地域・派生差分、HPフェーズ
        ↓  戦闘状態から次を選択
選択規則
  開幕、HPフェーズ、直前履歴、クールダウン、重みによる長期的な流れ
```

目的は、敵が単純な固定順や高速連打にならず、10秒リールから危険と休止を読める状態を
保ったまま、戦闘ごとに長期的な展開差を作ることである。200体それぞれへ5～6個の
完全新規パターンを作るのではなく、まず40種類の汎用タイミングを組み替えて使う。
実戦で不足した順序だけを後から追加し、件数自体を量産目標にしない。

## 2. 維持する既存契約

- 通常の敵行動値は固定値とし、リール表示後に非表示乱数で増減させない。
- パターンは行動だけでなく意図的な休止を含む。
- 10秒リールへ一度公開した行動の種類、値、実行時刻は、HP変化やフェーズ移行で変更しない。
- 選択結果は戦闘seedから決定的に再現できるようにする。
- 画面コードは行動値、時刻、HP閾値、重みを持たない。
- 通常／強化／精鋭／ボスの威力補正とHP補正は、既存の
  `JourneyEnemyVariantDefinition`と遭遇合成から引き続き与える。
- 既存タイムラインは明示的に移行するまで現在の循環順を保つ。

## 3. 個別行動

### 3.1 データ

敵プロファイルごとに個別行動表を持たせる。個別行動と共有タイミングを別物として扱い、
同じタイミング型へ敵ごとの攻撃内容を結合できるようにする。

```text
RealtimeEnemyActionContent
  id
  displayName
  kind
  motionLane
  value
```

- `value`は攻撃なら一発のダメージ、防御なら獲得ブロックを表す。
- `kind`は初回実装では現行の`NormalAttack / ComboAttack / Guard /
  JumpReaction / BraceReaction`だけを使う。
- `motionLane`は`Default / High / Low`を持ち、行動ルールとは独立してリール画像と
  予兆中の高い／低い構えを選ぶ。`Default`は従来のkind別表示を維持する。
- 状態異常、回復、召喚など新しい効果種別はこの段階では追加しない。
- タイミング側のstepは`executeOffset / kind / telegraphLead / hitCount / hitSpacing`を持つ。
  技名、表示名、威力は持たない。
- runtime構築時にstepの`kind`と一致する敵固有コマンドを決定的に結合する。
- 地域・個体・強度による威力倍率は、個別行動をruntimeへ組み立てる時に一度だけ適用する。
- 敵ごとの`timingScale`はduration、実行秒、予告、連撃間隔、クールダウンを一括で伸縮する。

### 3.2 移行互換

現在のstep内`kind / damage / telegraphLead / hitCount / hitSpacing`は直ちに削除しない。

1. 敵プロファイルに`commands`があれば、stepの`kind`へ一致するコマンドを結合する。
2. `commands`がなければ共有action参照または現在のstep内値を使う。
3. パイロット移行完了後、監査で旧形式の残数を表示する。
4. 全対象移行と実画面確認が終わるまで旧フィールドを削除しない。

## 4. 共有の長期行動パターンと敵ごとの行動セット

### 4.1 共有パターンカタログ

長期タイミングは敵アセット内へ複製せず、40種類の汎用カタログを初期正本にする。
正確な最終数は、5～6個の組み合わせで200体の役割を作れるかを見ながら決め、
数を埋めること自体は目的にしない。

一つの共有パターンは次を持つ。

```text
id
role                  Opening / Standard / Pressure / Recovery / Signature / Transition
duration
steps[]
baseWeight            0以上の整数
allowedPhaseIds[]
cooldownGroupId       任意
cooldownSeconds       パターン終了から次回候補へ戻るまで
maxConsecutive        同じパターンの最大連続数
maximumUsesPerBattle  0なら無制限
previousPatternWeightOverrides[]  任意。固有敵だけが使う
```

- `role`は監査と長期リズムの説明に使い、威力を自動補正しない。
- `cooldownGroupId`により、別IDのジャンプ反応と踏ん張り反応を交互に連打する抜け道を防ぐ。
- `previousPatternWeightOverrides`は「防御準備の後に圧力が高まりやすい」など、固有の文法が
  必要な精鋭・ボスだけに使う。通常敵へ全組み合わせの遷移表を要求しない。

### 4.2 敵ごとの行動セット

各敵は共有カタログから原則5～6パターンを参照する。

```text
RealtimeEnemyBehaviorLoadout
  patternReferences[5～6]
  commands[]
  timingScale
  openingPatternId
  fallbackPatternId
  phases[]
  patternWeightOverrides[]
```

- 地域固有通常敵は、役割を成立させる基本5～6タイミングを選ぶ。
- 同系統の雑魚敵や見た目を変えた派生個体は、基本セットの大半を共有する。
- 地域差・強化差はまず敵固有コマンドを差し替え、タイミング文法は大半を共有する。
- 精鋭は既知のタイミングを残し、固有コマンド、速度倍率、重み・フェーズ差で強敵化する。
- ボスは固有コマンド比率を高くし、必要な場合だけ専用タイミングを追加する。
- 同じパターン参照へ敵ごとの威力補正を掛けられるため、数値差だけを理由に複製しない。
- 200体×5～6個をすべて別制作する方式にはしない。

### 4.3 カタログの内訳目安

最初から総数を固定せず、次の用途が不足しないかを監査する。

| 区分 | 主な用途 |
|---|---|
| 汎用基本 | 単発攻撃、防御混じり、短い圧力、長い休止 |
| 武器・輪郭系統 | 鐘、槌、鉤、爪、術式など共通の予兆文法 |
| 地域差分 | 灰、市場、水没、書庫など環境を持ち込む行動 |
| 精鋭差分 | 既知セットへ1～2個足す強い判断要求 |
| ボス固有 | 開幕、フェーズ移行、切り札、専用休止 |

量産時は「新しい敵だから6個追加」ではなく、既存カタログで役割を組めるかを先に確認し、
不足する判断・リズムだけを新規パターンとして追加する。

## 5. HPフェーズ

### 5.1 フェーズ定義

フェーズは敵ごとの行動セット内に順序付きで保存する。同じ共有パターンでも、敵によって
どのフェーズで選びやすいかを変えられる。

```text
RealtimeEnemyPhaseContent
  id
  enterAtOrBelowHealthRatio
  patternWeightOverrides[]
  transitionPatternId       任意
```

- HP比率は`currentHp / maximumHp`で求める。
- フェーズは戦闘中に後方へ戻らない。敵が将来回復しても以前のフェーズへは戻さない。
- フェーズ移行だけではHP、威力、パターン速度を自動変更しない。変化は候補と重みだけに限定する。
- 一度の攻撃で複数閾値を越えた場合は、到達した最も低いHPフェーズへ直接入る。
- `transitionPatternId`がある場合だけ、次の未確定境界で一度実行する。未設定なら通常選択へ進む。
- 通常敵へ複数フェーズを必須化しない。複数フェーズは特色通常、精鋭、ボスへ選択的に使う。

### 5.2 予告済み行動との関係

HP閾値を越えた瞬間にリールを差し替えない。

```text
HP閾値を越える
  → 新フェーズをpendingにする
  → すでに選択・予約・表示したパターンは完走する
  → 次の未確定パターン選択から新フェーズを使う
```

したがって、フェーズ変化には予告保護分の遅延が生じる。この遅延を
`phaseTransitionDelay`として監査し、長すぎる場合は行動を消すのではなく、パターン長または
先読み確定範囲を調整する。

## 6. 次パターンの選択規則

### 6.1 選択の入力

選択時点で次だけを読み取る。

```text
battleSeed
actorId
currentHp / maximumHp
currentPhaseId / pendingPhaseId
currentBattleTime
nextPatternStartsAt
previousPatternId
consecutiveCount
patternUseCounts
cooldownReadyAtByGroup
scheduledPatternCount
```

HPは選択時点の実値を使う。将来HPを予測しない。

### 6.2 優先順位

1. 戦闘開始時に`openingPatternId`が設定されていれば一度だけ選ぶ。
2. pendingフェーズに`transitionPatternId`があれば、次の未確定境界で一度だけ選ぶ。
3. 現在フェーズで許可されていないパターンを除外する。
4. `maximumUsesPerBattle`へ達したパターンを除外する。
5. `nextPatternStartsAt`がクールダウン解除時刻より早いパターン／グループを除外する。
6. `maxConsecutive`へ達した同一パターンを除外する。
7. 残った候補へ次の整数重みを掛け、決定的な重み付き抽選を行う。

```text
effectiveWeight =
  baseWeight
  × phaseWeightPercent
  × previousPatternWeightPercent
```

割合は整数パーセントで保存し、未指定は100とする。0はその条件で選択禁止を表す。

### 6.3 候補がなくなった場合

- 各ルール選択プロファイルは、全フェーズで使用可能、クールダウンなし、使用回数無制限の
  `fallbackPatternId`を必須とする。
- 通常候補が0件ならfallbackを選び、警告と選択文脈を記録する。
- runtimeがクールダウンやフェーズ制限を黙って破って別パターンを選ぶことはしない。
- 静的監査では、fallbackへ到達し得る組み合わせを警告し、通常運用でのfallback発生を0件にする。

### 6.4 決定性

抽選値は`battleSeed + actorId + scheduledPatternCount + phaseId`から作る。
候補配列はpattern IDのordinal順へ正規化してから抽選し、Unityアセット内の並び替えで結果を
変えない。保存・再開ではseedだけでなく、フェーズ、履歴、使用回数、クールダウン解除時刻、
選択済みパターンを保存対象にする。

## 7. 旧循環方式との共存

選択モードを明示する。

```text
RealtimeEnemySelectionMode
  CyclicLegacy
  RuleBased
```

- 未設定・旧アセットは`CyclicLegacy`として現在と同じ配列順を繰り返す。
- `RuleBased`はopening、fallback、フェーズ、重み、クールダウンの監査に合格した
  プロファイルだけ有効化できる。
- 一括変換せず、パイロット3体を実画面と計測で確認してから量産対象へ広げる。

## 8. 最初のカタログ・行動セット試作案

最初はA / C / G / J / Bの順番と相対時刻だけを持つ汎用タイミング40種類を作る。
そのカタログから各敵へ6個を割り当て、敵側の5コマンドを結合する。強弱はまず
`timingScale`で全体を伸縮し、固有の順番が必要になった精鋭・ボスだけ専用型を追加する。

| 枠 | 行動セット案 | 目的 |
|---|---|---|
| 再登場通常 | 灰鐘／水封じの巡視兵は6個中5個を共有し、地域固有1個だけを差し替える | 同系統だと分かりながら地域差が出るか |
| 地域固有通常 | 煤管さらいは汎用2～3個、系統共通1～2個、固有1個の計5～6個 | 共有中心でも固有の役割が成立するか |
| 地域固有精鋭 | 炉灰の執行官は既知3～4個、精鋭固有1～2個の計5～6個 | 既知予兆を残しながら強敵化できるか |
| ボス | 番人ボスは汎用・系統共通を一部残し、固有開幕・移行・切り札を含む6個以上 | ボス独自の長期展開を作れるか |

初期ルール案:

- 再登場通常の地域違いは、威力倍率だけでなく行動セットの1個を地域固有へ差し替える。
- 地域固有通常は少なくとも1個、精鋭は1～2個、ボスは複数の固有コマンドを持つ。
- 反応要求パターンは共有クールダウングループへ入れ、異なるパターンIDを交互に使って
  反応要求を連打することを防ぐ。
- HPフェーズは行動セット内の5～6個から選ばれやすいものを変え、共有パターン自体を
  敵ごとに複製しない。

40タイミング型の具体的な秒数は草案値とし、実戦の総消耗計測後に調整する。

## 9. 監査とテスト

### 静的監査

- command IDとpattern IDの重複、欠落参照、各step種別に対応するcommandの不足。
- 汎用タイミングへ具体action IDやdamageが混入していないこと。
- stepがpattern durationを越えていないこと。
- フェーズ閾値の順序と範囲。
- 各フェーズに通常候補とfallbackがあること。
- opening、transition、fallbackが存在し、その用途に適合すること。
- cooldown groupと最大連続数を加味した候補枯渇。
- 既存の平均DPS、10秒最大行動数・最大被害、最短予告、最長休止、反応要求数。

### 決定的シミュレーション

- 同じseedと同じHP推移で同じパターン列になる。
- 候補配列やアセットの並び順を変えても結果が変わらない。
- 1000 seedで各フェーズの選択率が設定重みに収束する。
- 同一パターン最大連続数、反応要求の連続回数、cooldownを破らない。
- HP閾値通過後、公開済み行動を変えずに新フェーズへ移る。
- 一撃で複数閾値を越えた時に最低HPフェーズへ一度だけ移る。
- フェーズ移行直後の10秒最大被害と`phaseTransitionDelay`を出力する。

### 実戦計測

既存の6体比較に次を追加する。

- パターン別使用率と最大連続数。
- フェーズ別滞在秒数と、フェーズごとの実被害。
- 閾値通過から新フェーズ最初のパターン開始までの秒数。
- 反応要求同士の最短間隔。
- 最短・平均・P90撃破秒数、HP損失、消耗品使用数、防御失敗数。
- 急行・標準・低速の各遠征における総HP損失。

## 10. 実装境界

承認後も最初の実装では次を行わない。

- 状態異常、回復、召喚など新しい行動効果の追加。
- HPフェーズによる自動的な威力・速度上昇。
- 予告済み行動のキャンセルや差し替え。
- 全敵アセットの一括移行。
- UIの新規レイアウト変更。
- 単戦結果だけを根拠にしたHP・威力の再調整。

## 11. 承認が必要なゲームルール

次のゲームルールは2026-08-22に草案実装へ進む方針として確認済み。

1. 次パターンは固定順ではなく、戦闘seedによる決定的な重み付き選択を採用する。
2. HPフェーズは後戻りせず、候補と重みだけを変更する。威力・速度は自動上昇させない。
3. リールへ公開済みの行動を優先し、フェーズ変更は次の未確定パターンから反映する。
4. 反応要求は個別パターンだけでなく共有クールダウングループで連続を制限する。
5. 通常候補がない時は制約を黙って緩和せず、明示fallbackを実行して監査警告を残す。
6. 最初は40種類の汎用タイミングカタログを作り、7体へ6個ずつ割り当てる。
7. 汎用タイミングは技名・威力を持たず、敵固有コマンドと種類で結合する。
8. 敵の基本速度差はタイミング全体の倍率で与え、順序自体は必要な場合だけ専用化する。
