# シームレス遠征・不足点監査

> 履歴資料。2026-08-14時点の監査であり、現在の不足一覧ではありません。
> 現行の方針と作業順は [`JOURNEY_PRODUCT_PLAN.md`](JOURNEY_PRODUCT_PLAN.md) を正本とします。

更新: 2026-08-14

対象は `JourneyTravelGameplayPrototype`。現状は方向性を評価する縦切りプロトタイプであり、
本番遠征の完成画面ではない。以下はユーザー確認前の実装候補一覧。

## P0: 本番化前に設計を決める項目

1. **本編RunStateとの接続**
   - 現在は専用の仮RunStateを生成するため、HP、荷物、戦闘結果、日数が本編へ戻らない。
   - 既存の `CourierRouteSystem`、`BackpackSystem`、中継荷造りへ同じRunStateを渡す必要がある。

2. **回収物とパッキングの接続**
   - ミニゲーム報酬は `recoveredCargoCount` の数値だけ。
   - 実アイテム、未整理荷物、一時保留枠、捨てる判断のどこへ接続するか未決定。

3. **遠征全体のテンポ設計**
   - 各区間に同じ時点でミニゲームが出るため予測可能。
   - 「眺める区間」「短い操作」「重要判断」「危険予告」の出現比率と最低間隔が必要。
   - 早送り時に省略する演出と、省略してはいけない判断を決める。

4. **遠征状態の保存・復帰**
   - 区間途中、イベント中、戦闘中の保存と再開がない。
   - アプリ終了、敗北、開発者画面往復時の復元規則も必要。

5. **コンテンツをコードから分離**
   - 台詞、天候、区画色、ミニゲーム順、ランドマーク位置がPresenterへ直書きされている。
   - `JourneyBiomeDef`、`JourneyBeatDef`、`JourneyEncounterDef` 相当のデータ化が必要。

## P1: 体験上すぐ気づく不足

### 移動・背景

- 遠景と中景は実質2組、地面は全区画共通で、長時間では反復が分かる。
- 色変化が区間進捗ごとにリセットされるため、遠征全体の昼夕夜になっていない。
- ランドマークが各区間20%地点に固定出現し、自然な場所の構成になっていない。
- 霧、雨、煤、窓明かり、地面反応など、前後レイヤーをつなぐ環境現象がない。
- キャラを背景から抜く局所照明・リムライトがなく、暗い区画で輪郭が沈み得る。
- 戦闘時に人物だけを上へ持ち上げているため、専用の接地線や影がないと浮いて見える可能性がある。
- 背景タイルの継ぎ目、同じ建築の反復、ランドマークとの遠近比を実画面で検査できていない。

### ミニゲーム

- スタンプの針と画面内の小包が視覚的につながっておらず、「何を操作しているか」がまだ弱い。
- 荷崩れも針だけで、実際の荷物・バッグ・キャラ姿勢が傾かない。
- 2種類が交互に出るだけで、区画、荷物、天候、選択結果による意味の違いがない。
- ×2中は判定時間が2倍速になるが、景色は0.5倍固定。難度と表示が一致していない。
- 成功帯、Perfect、Good、失敗の音・接触感・予告がない。
- 初回説明、練習、入力変更、苦手な人向け自動処理がない。
- ミニゲーム中に世界を進ませるならルート距離も進めるべきか、演出距離として扱うか未決定。

### 戦闘

- 歩行・停止以外のキャラ絵がなく、攻撃、被弾、防御、勝利、敗北の状態が見た目に出ない。
- 敵も静止画1体だけで、予備動作、攻撃、被弾、死亡がない。
- 敵意図は数値だけで、攻撃種別、状態異常、複数回攻撃への視覚的な予告が不足。
- プレイヤーのブロック、状態異常、山札、捨札、手札上限が見えない。
- カードは固定5枠なので、手札が6枚以上になると操作できない。
- カードを小さくしたため本文10pxで、本番の可読基準を下回る。選択時拡大か詳細欄が必要。
- カード種別、対象、消費、使用不能理由、バッグ内の出所が瞬時に判別できない。
- 敵を倒したカードでは敵が即座に非表示になり、最後のダメージ演出が見えない可能性がある。
- 複数敵、巨大敵、味方追加、召喚物に対応する舞台レイアウトがない。
- 戦闘終了から結果・報酬・移動再開までの一連の演出が未完成。

### イベント・選択

- イベント絵が共通で、場所や人物の固有性がない。
- 選択肢が汎用2択で、成功条件、時間消費、荷物への影響を比較しにくい。
- 商人、中継、施設、連続イベント、過去選択を覚えるイベントが未接続。
- 分岐画面は次の1区間だけを示し、遠征全体でどこにいるか分からない。
- 「危険」「回収」などの言葉が、実際に何が起きるかまで伝えていない。

### 音と演出

- 足音、荷物音、環境音、UI音、攻撃音、被弾音がない。
- 区画ごとの環境音と戦闘曲を滑らかに切り替える音響状態がない。
- 重要ランドマークや危険接近を音で先に知らせる仕組みがない。
- 画面振動はあるが、強度設定・無効化設定がない。

## P2: 品質・運用上の不足

- Spaceが歩行試験コードとミニゲームの両方で処理され、入力競合する可能性がある。
- 直接 `Input.GetKeyDown` を使っており、ゲームパッド、キー変更、タッチへ広げにくい。
- UI初期フォーカスと方向ナビゲーションが未定義。
- 色だけに頼らない成功帯表示、文字拡大、振動軽減、ミニゲーム補助設定が不足。
- 1280x720以外のアスペクト比、セーフエリア、長文、6枚以上の手札を未検証。
- 小物を都度生成・破棄し、スプライトもランタイム生成している。量産時はプールとAtlas化が必要。
- 1ファイルが1000行を超え、移動、イベント、戦闘、演出、ワールド生成が同居している。
- 状態別スクリーンショット、低FPS、ポーズ、倍速、長時間反復の自動テストがない。
- 旧 `ANIMATION_PROTOTYPE.md` は現在の操作と報酬仕様に一致していない。

## 推奨する次の確認順

1. 本編RunState・パッキングへ接続する範囲
2. 移動中に何をするゲームなのかというテンポ規則
3. 戦闘の情報配置と必要なキャラ状態絵
4. 背景を何区画・何レイヤー・何変種で作るか
5. イベント、商人、中継を同画面に残す範囲
6. 音、入力、アクセシビリティ、保存

## ユーザー追記欄

- ミニゲームは2種類より増やしたい。
- 大きな分岐では、画面全体に紙面風の2案を出し、イメージ絵、フレーバー、細かな効果を見せたい。
- 小さな分岐まで同じ重いUIにせず、大分岐と小分岐を分けたい。
- 戦闘はカードと必要情報を収めるため、構造から見直したい。
- 移動中に配達印をどう使うか再設計したい。
- 遠征全体の位置確認には既存航路台帳を活用したい。
- 基本は自動で目的地へ着ける方がよい。地図で方向を変えるなら別のメリットを持たせたい。
- 音は素材制作前なので今回の優先対象外。
- 入力競合などの技術的負債は早めに処理する。
