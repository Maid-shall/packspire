# シームレス遠征・プロダクト計画

更新: 2026-08-18  
状態: 現行の正本  
対象: 遠征開始から3階層の探索、分岐、地点、戦闘、帰還、完全踏破まで

## 1. 目的

遠征を、別々の試作画面の集合ではなく、一続きの「配達の旅」として完成させる。
移動は原則自動で進み、プレイヤーは経路、カード使用、危険への反応、配送中の問題へ
判断を集中する。

本書は次を一か所で管理する。

- 採用済みのゲーム方針。
- まだ決めていない重要事項。
- 現在確認できている欠落と不具合。
- 実装順と各段階の完了条件。

## 2. 採用済みの方針

- 遠征は3階層制とし、各階層は途中分岐と再合流を繰り返しながら奥へ進む有向非巡回グラフとして構成する。
- 各階層の戦闘数は経路によって4～8戦程度に変動し、最後に階層ボスを置く。
- 探索寄り、均衡、突破寄りは階層全体を固定するルート名ではなく、各分岐で選び直せる局所的な傾向とする。
- 探索寄りの区間は戦闘が少ない代わりに日数を使い、突破寄りの区間は日数を抑える代わりに戦闘が増える。
- 経路選択は正解探しではなく、日数、HP、危険、遭遇、報酬、景色を交換する判断とする。
- 階層ボス撃破後は帰還か次階層への続行を選ぶ。帰還後の次遠征は第1階層から始める。
- 帰還または完全踏破では遠征中に得た全戦利品を持ち帰る。
- 死亡時は現在バックパック内にある新規装備だけを持ち帰り、未収納の新規装備を失う。
- 持込装備はバックパック外へ移しても所有権を失わない。
- バックパック内の装備は拠点・遠征中を問わずカード化し、中継地点で詰め替えられる。
- 日数による即時失敗は廃止し、全ダンジョン共通の日数区分で遭遇・報酬テーブルを切り替える。
- 配達人、航路台帳、印、中継局、荷札のテーマは維持し、目的を「崩壊した配送網の探索・復旧」へ再定義する。
- 通常移動は横スクロールの同一舞台で続ける。
- 大分岐は横スクロール領域へ左右2枚の紙面経路票を表示する。
- 航路台帳は別の進行画面ではなく、遠征上へ重ねる確認用オーバーレイとする。
- 戦闘は移動と同じ舞台で開始し、カードを任意時点で使うリアルタイム方式とする。
- 敵行動は10秒先まで見える縦リールで予告する。
- 敵行動は単発で画面を埋めず、休止と密集を含む長い行動パターンから生成する。
- エナジーと手札補給は行動票ではなく、同じ時間軸上の帯で表す。
- バッグへ回収荷物をどう接続するかは別途決定するまで保留する。
- 音は素材方針が決まるまで現在の優先対象から外す。

## 3. 現在地

### 成立している基盤

- 多層パララックス、道幅、3バイオーム、前景、環境演出。
- 自動移動、大分岐、航路台帳、配達印の基本操作。
- イベント、6種の路上タスク、戦闘、報酬画面への最低限の接続。
- リアルタイム行動列、10秒表示、長い敵行動パターン、補給帯。
- カード、エナジー、山札、捨札、HP、ブロックの本編データ接続。
- 開発者メニューから本編RunStateを使った遠征・戦闘確認。

### 現在の評価

機能は一周できるが、商品として必要な場面転換、敵バリエーション、地点内容、
遠征の始まりと終わりが不足している。背景や戦闘画面の単体調整より、まず
`移動 → 遭遇 → 戦闘 → 戦利品 → 移動復帰`を一本の体験として仕上げる。

## 4. 実装前に決めるP0設計

### P0-A 新戦闘用の敵行動・遭遇ルールを更新する

既存の
[`ENEMY_ENCOUNTER_BALANCE_FRAMEWORK.md`](../../../ENEMY_ENCOUNTER_BALANCE_FRAMEWORK.md)
はターン制戦闘を基準にしている。敵単体→遭遇→遠征総消耗という骨格は維持し、
新しいリアルタイム戦闘向けに次を追加する。

#### 敵量産の作成契約

最終的な敵数は通常100、強化50、精鋭30、ボス20の合計200体を目標とする。
200体すべてへ固有の役割設計を要求せず、次の部品を分離して再利用する。

敵の再登場は全体方針ではなく量産手段の一つとする。通常敵の一部と精鋭の一部だけが
地域をまたいで同系統として再登場し、各地域には地域固有の通常敵と地域固有精鋭を必ず置く。
詳細と最初の2地域試作は
[`ENEMY_PRODUCTION_RULES.md`](ENEMY_PRODUCTION_RULES.md)
を正本とする。

1. 敵本体のID、名前、基礎HP、アートは`JourneyEnemyDefinition`へ保存する。
2. A / C / G / J / Bの順序と時刻だけを持つ汎用タイミングを共有カタログへ保存し、
   各敵は原則5～6個を`RealtimeEnemyTimelineProfile`から参照する。技内容と値は敵固有
   コマンドへ置き、基本速度差はタイミング全体の倍率で与える。
3. 通常／強化／精鋭／ボスの分類とHP・威力補正は`JourneyEnemyVariantDefinition`へ保存する。
4. `JourneyBattleEncounterProfile`は上記3部品と出現条件だけを束ね、同じ行動型を別の敵で共有できるようにする。
5. HP、フェーズ、直前パターン、クールダウンから次パターンを選ぶ。
6. 行動時刻と表示値は画面コードへ直書きしない。
7. 固有役割や固有行動は、精鋭・ボス・特色を持たせたい通常敵にだけ追加する。

#### 新たに測る値

- 平均DPSと10秒内最大被害。
- 最短・平均・P90撃破秒数。
- 攻撃が密集する時間と、考えられる休止時間。
- 予告開始から入力期限までの反応猶予。
- ジャンプ／踏ん張りを要求する頻度と連続回数。
- カード判断、反応入力、状態異常が重なる操作負荷。
- エナジー・手札補給まで耐える必要時間。
- 同じパターンの連続、フェーズ移行直後の最悪被害。
- 戦闘単体のHP損失だけでなく、一遠征内の遭遇回数を掛けた総消耗。

#### 遭遇ルール

- 戦闘ノードは敵IDまたは遭遇IDを持ち、全地点で番人を共有しない。
- 小遭遇、通常、危険、精鋭、ボスの目標消耗を再校正する。
- 複数敵を実装するまで、増援、連戦、敵フェーズを同じ遭遇契約で扱う。
- 10秒表示を超える行動は消さず、表示上限超過を検査する。
- 反応必須攻撃だけで戦闘を埋めず、カード判断だけで受ける通常攻撃も混ぜる。
- 強敵は単純な高速化ではなく、予告可能な密集と十分な休止を組み合わせる。

#### 完了条件

- 番人を含む最低3種類の敵で、本体・共有行動型・個体補正をデータだけで差し替えられる。
- 基準ロードアウトによる静的監査と複数シードの戦闘結果を出せる。
- 10秒リールを見て最大危険、反応要求、休止時間を読み取れる。
- 経路ノードから正しい遭遇プロファイルを起動できる。

### P0-B 報酬・帰還・死亡時回収ルール（採用済み）

既存の`戦闘 → 装備選択画面`を毎戦闘では使用しない。ハクスラとしてランダム装備を
多数持ち帰れることと、ローグライトとして続行時に損失リスクがあることを両立する。

#### 戦利品の状態

| 状態 | カード化 | 死亡時 | 帰還・踏破時 |
|---|---:|---:|---:|
| 持込装備 | バックパック内のみ | 保持 | 保持 |
| 新規装備・バックパック内 | する | 持ち帰る | 持ち帰る |
| 新規装備・未収納 | しない | 失う | 持ち帰る |

- 保護判定は「一度入れたか」ではなく、死亡時点でバックパック内にあるかで決める。
- 中継地点では新規装備を含めて詰め替え、カード構成を即時再構築できる。
- 未収納戦利品の所持数にはバックパック容量を適用しない。

#### 報酬源

- 通常戦はラン内消耗品など最低限の成果を保証し、装備は確率で落とす。
- 危険戦は上位消耗品と高い装備抽選率を持つ。
- 精鋭戦は装備を1個以上保証する。
- 階層ボスは特殊報酬と高品質装備を保証する。
- 探索地点は装備数、装備種、特性を狙いやすくし、戦闘だけを装備収集の正解にしない。
- 長い装備未獲得が続かないよう、抽選には内部保証を持たせる。

#### ラン内消耗品

旧消耗品システムを捨てず、新リアルタイム戦闘と探索へ接続し直す。
消耗品は遠征中だけ所持・使用でき、帰還後の恒久装備枠とは分離する。

- 戦闘用: 体力回復、一定時間の攻撃上昇、一定時間の防御上昇、敵行動列の遅延。
- 探索用: 日数短縮など、経路上で使う効果も許可する。
- 通常戦では装備が落ちなかった場合も、消耗品またはラン内資源によって最低限の成果を残す。
- 使用UIは現行の手札、戦闘リール、エナジー、山札・捨札を圧迫しない専用領域に置く。
- 配置と外観はUnity実画面上で候補を比較してから確定し、効果データと処理をUIより先に分離する。

#### 遠征の終了

- 死亡、階層ボス後の自主帰還、第3階層の完全踏破を遠征の終了条件とする。
- 階層ボス後に続行した場合、未収納戦利品は次階層でも危険に晒される。
- 帰還すると次の遠征は第1階層から開始する。

### P0-C 遠征全体のデザインをブラッシュアップする

個別画面ではなく、次の体験列を一本のデザインとして再設計する。

```text
遠征準備
→ 出発
→ 自動移動
→ 路上の前兆
→ 小判断／大分岐／地点
→ 戦闘またはイベント
→ 戦利品・消耗品獲得
→ 同じ場所へ復帰
→ 中継地点で詰め替え
→ 階層ボス
→ 帰還または次階層
→ 完全踏破または死亡
→ 遠征結果・戦利品確定
```

各接続について、開始条件、入力ロック、カメラ、人物姿勢、UIの入退場、背景状態、
結果の保存先を一枚のフローマップへする。全画面モックを増やす前に、現在のUnity実画面を
一段階ずつ撮影して比較する。

## 5. P1 接続を商品レベルへする

### P1-1 出発

- 遠征名、対象階層、現在の危険段階、主要危険、持込印を出発前に確認する。
- 現在の目的不明な冒頭6.5秒歩行を、出発演出または最初の短い区間へ置き換える。
- 最初の大分岐までに、プレイヤーが「崩れた配達網を奥へ踏査し、帰還可能地点まで到達する」目的を言える状態にする。

### P1-2 分岐と移動

- 押印、経路確定、日数加算、景色転換、歩行再開の順を視覚と内部処理で一致させる。
- 1日路と2日路の違いを、秒数だけでなく景色、休止、地点数でも伝える。
- 一択経路を自動確定する場合も、通過地点を短く表示する。
- 小イベントに毎回全画面結果を出さず、重要度に応じてトースト、小票、全画面を使い分ける。

### P1-3 戦闘突入

- 遭遇前兆、歩行減速、敵の進入、戦闘姿勢、HUD・手札・リール入場を順番に見せる。
- 0.72秒の共通バナーだけで戦闘へ切り替えない。
- 敵の名前と遭遇理由をデータから表示する。
- 戦闘入力を解放する瞬間を視覚的に示す。

### P1-4 戦闘終了と報酬

- 最後の着弾、敵の撃破／退却、リール停止、勝利確認を見せる。
- P0-Bで決めた方式へ報酬を接続する。
- 報酬後は現在のバイオーム、道幅、地点、天候、一時状態を復元する。
- 同じ道へ戻ったと分かる短い復帰演出を入れる。

### P1-5 階層終了・帰還・完全踏破

- 各階層ボスへ近づく専用区間とランドマークを用意する。
- ボス撃破後に戦利品、バックパック、次階層の危険を確認して帰還か続行を選ぶ。
- 日数、経路、戦闘、回収、印使用、保護戦利品、未収納戦利品を専用結果へまとめる。
- 死亡、途中帰還、完全踏破を別の結果として扱い、汎用GameClear/GameOverだけで終了しない。

## 6. P2 地点内容とテンポ

### 階層とノード構成

- 各階層はプレイヤーが通過する経路上で戦闘約50%、イベント約20%、休憩・中継約20%、その他約10%を初期目標とする。
- 比率は生成する全ノード数ではなく、代表的な経路を実際に一周した時の通過数で監査する。
- 一階層を通して探索寄りに選べば戦闘4～5回、均衡なら6回前後、突破寄りなら7～8回を目安とする。ただし途中の分岐で別傾向へ移れる。
- 休憩・中継を全経路へ均等配置せず、探索側ではイベント、休憩、その他地点へ寄りやすく、突破側では戦闘が連続しやすい構成にする。
- 各経路は上記の比率へ機械的に一致させず、階層全体と複数の代表経路を合わせて目標比率へ収束させる。
- 全経路を奥方向へ進む有向非巡回グラフとし、後戻り、同一地点の再利用、無限稼ぎを許可しない。
- 各地点の選択肢は最大2件に抑え、複数回の分岐・再合流後に階層ボスへ到達する構造にする。
- 初期生成は一階層8区間、最大3列、一階層32通りを基準とする。三階層を通した経路列は32,768通りになる。

### 日数と危険段階

- 日数による即時失敗は発生させない。
- 日数は遠征全体で累積し、階層移動ではリセットしない。
- 全ダンジョン共通で、0～10日を「静穏」、11～20日を「警戒」、21～35日を「追跡」とする。
- 36日以降も通常は「追跡」を維持する。専用フラグを持つダンジョン、または特定イベントで解禁された場合だけ第四段階「異常」へ移行する。
- 段階は単純な敵能力補正ではなく、敵行動、精鋭候補、イベント、探索報酬、装備品質の抽選表を変える。
- 高日数は高リスクだけでなく高リターンも持ち、最短路だけを唯一の正解にしない。
- 代表経路シミュレーションでは閾値を動かさず、急行なら第三層ボスが第二段階、標準なら第二～第三段階、低速なら第三段階になるよう各地点の日数コストを調整する。
- 各区間にはイベント結果とは別の基礎日数を持たせる。イベント、消耗品、印による増減は実行時補正として区間日数へ加算する。
- 全階層の経路組み合わせを静的監査し、最短日数、中央50%境界、最長日数、各到達段階を表示できるようにする。

### イベント

- ノードごとに本文、選択肢、条件、結果、日数、報酬をデータ化する。
- 現在の「慎重＝成功／急ぐ＝+1日」という共通結果をやめる。
- 重大イベントと小さな路上判断を分ける。

### 路上タスク

- 全非戦闘区間の進行42%へ必ず出す固定規則をやめる。
- 経路、天候、荷物、直前イベントから候補と発生率を決める。
- 対象物の出現、接近、操作受付、通過、結果までを共通導入として作る。
- 轍避けはプレイヤーが判定を進める方式をやめ、障害物が時間で接近する方式へ直す。
- 成功報酬をすべて未整理荷物+1にせず、日数、HP、印、カード、荷物状態へ分ける。
- 連続出現を禁止し、何も起きない静かな移動時間を残す。

### 航路台帳と配達印

- 台帳の選択可能地点を毎回現在の`CourierRouteState`から算出する。
- 印使用、経路確定、日数変化を一つの操作結果として見せる。
- 台帳を閉じる操作をEscape／戻るへ統一する。

## 7. P3 堅牢性・性能・アクセシビリティ

- 分岐押印、背景転換、ミニゲーム結果の待機を一時停止対応へ統一する。
- F10で本編Runを破棄する前に確認するか、開発ビルド専用にする。
- 戦闘ログを非表示のまま重要説明の唯一の出力先にしない。
- 初戦闘でリール、補給帯、カードホバー中のスロー、ジャンプ／踏ん張りを短く説明する。
- 色に加えて形状と印で攻撃、防御、補給、反応要求を判別できるようにする。
- キー変更とゲームパッド操作を入力層へ移す。
- リールの毎フレーム全消去・全再設定を差分更新へ置き換える。
- 10件を超える予告を黙って非表示にせず、監査エラーまたは縮約規則を持つ。
- 1280x720論理座標を基準に、16:9以外とUIスケールを検査する。
- アプリ終了後も遠征地点、経路、背景、戦闘／報酬復帰状態を再開できるようにする。

## 8. 必須の統合試験

- 出発→最初の大分岐。
- 分岐→移動→イベント→結果→次分岐。
- 分岐→移動→戦闘→報酬→同じ区画へ復帰。
- 戦闘敗北→遠征失敗。
- 最終地点→引き渡し→遠征結果→ホーム。
- 分岐押印中、背景転換中、ミニゲーム結果中に一時停止／台帳を開く。
- 報酬復帰後も正しいバイオーム、道幅、HP、日数、印、行動順が残る。
- 10秒内に10件を超える敵行動がある場合の表示保証。
- 異なる遭遇プロファイルを経路ノードだけで差し替える。

## 9. 実装順

1. ✅ P0-Bの採用ルールを状態モデルとセーブへ反映する。
   - `startingItemUids`で持込品と新規品を区別する。
   - 敗北時は持込品と死亡時点でバッグ配置済みの新規品だけを保護する。
   - 帰還・完全踏破時は全戦利品を確定し、帰還と完全踏破を別の終了理由として記録する。
2. ✅ 旧ラン内消耗品を監査し、戦闘・探索で再利用できるデータ基盤を整える（効果量の調整は後続）。
3. ✅ 3階層、共通日数3段階＋条件付き第四段階、選択列別4～8戦を生成・検査できる航路モデルを作る。
   - 共通閾値と第四段階のダンジョン／イベント解禁状態を航路モデルへ反映済み。
   - 経路の基礎日数と、全組み合わせに対する急行／標準／低速の到達日数監査を追加済み。
   - 固定2本の経路を廃止し、一階層8区間、最大3列、32通りの分岐・再合流グラフへ変更した。探索／突破は固定ルートではなく地点ごとの傾向として途中変更できる。
   - 現在の基準値は急行18日、標準21日、低速24日。
   - 累積日数の正本を遠征航路モデルへ移し、旧航路の日数表示と同期する移行層を追加済み。旧15日締切による即時失敗は実行経路から除外した。
   - 生成済み3階層ノードに選択・地点解決・ボス再合流・次階層・完全踏破の実行状態を追加済み。基礎日数は選択した区間ごとに一度だけ適用し、途中の傾向変更でも二重加算しない。
   - シームレス遠征の分岐、自動進行、地点解決、戦闘報酬後の復帰、航路台帳の現在階層表示を生成済み3階層ノードへ接続済み。
   - 旧`CourierRouteState`は移行中の配達印・回収数互換データに限定し、進行の正本は`ExpeditionRoutePlan`へ統一した。
   - 戦闘ノードには決定済み遭遇IDを保存し、階層・日数段階・通常／ボス・列傾向・ダンジョン・抽選重みから遭遇プロファイルを決定的に選ぶ接続を追加済み。再開後も同じ敵になる。
   - 次はイベント・休息・探索内容を生成ノードからデータ選択し、階層ボス後の帰還／続行判断へ接続する。
4. 🚧 P0-Aのリアルタイム敵・遭遇規則を正本とデータへ反映する。
   - 行動周期、平均DPS、10秒内最大行動数・最大被害、最短予告、最長休止、反応要求数を静的監査できるようにした。

   - 量産目標は通常100、強化50、精鋭30、ボス20。補正値は初期実験値であり、遠征総消耗の計測後に確定する。
   - 灰市外縁／水没書庫に、再登場する鐘番系統2体、地域固有通常2体、地域固有精鋭2体を接続した。旧番人はボス専用へ移し、通常戦の全地点共有を終了した。
   - 地域固有枠と再登場系統を自動監査し、同じ行動リズムを保った地域火力差もデータだけで設定できる。
   - パイロット正本は[ENEMY_PRODUCTION_RULES.md](ENEMY_PRODUCTION_RULES.md)。開発者メニューから6遭遇を同じ新戦闘へ直接投入できるようにし、10秒行動圧と1000 seedの遭遇分布を[初期計測](ENEMY_PILOT_MEASUREMENT_2026-08-21.md)へ記録した。

   - 敵ごとの`timingScale`でduration、実行秒、予告、連撃間隔、クールダウンを一括伸縮できる。固有タイミングは精鋭・ボスで必要性が確認できた場合だけ追加する。

   - 封鐘の番人を一体目の戦闘演出正本とし、6ポーズ名、High / Lowの武器先端、各命中絵の接地点、光量を`JourneyEnemyBattlePresentationProfile`へ分離した。待機→予備動作→一回発光→命中絵と接地火花→完全不透明のまま0.24秒の減衰復帰→終端で一度だけ連撃姿勢または待機へ切替を戦闘確認所で実画面検証した。

## 10. 完成判定

遠征が完成したと言えるのは、次をすべて満たした時とする。

- 開始から帰還まで、開発者メニューを使わず一周できる。
- 各場面転換で、何が起きたか、なぜ止まったか、次に何を選ぶかが分かる。
- 同じ番人、同じイベント結果、同じ路上タスク報酬だけで10区間を埋めない。
- 戦闘報酬の回数と内容が、採用した遠征ループとして説明できる。
- 敵の強さをリアルタイム指標と遠征総消耗の両方で評価できる。
- 報酬や画面遷移を挟んでも現在地点と景色の連続性が失われない。
- 各階層ボス後の帰還判断と完全踏破が、通常ノードより明確に大きな体験になっている。
- Unityコンソール、統合試験、代表解像度、Profiler基準を通過する。

## 11. 戦闘の確定値とダイス運用（採用済み）

- 通常のプレイヤーカード、通常の敵行動、通常の消耗品ダメージは固定値とする。
- カード本文と敵行動リールに表示された値は、そのまま実際の基礎効果として保証する。
- リールで予告した値を非表示の乱数で上下させない。リアルタイム判断の信頼性を優先する。
- ダイスは廃止せず、特定役職、イベント、明示された特殊カードなど、ランダム性そのものが選択理由になる効果だけで使用する。
- ダイスを使う効果はデータ上で `DamageResolutionMode.TwoD6` を明示し、UIでも通常の固定値効果と区別できるようにする。
- 既定値は `DamageResolutionMode.Fixed` とし、追加カードが意図せずダイス判定になることを防ぐ。
