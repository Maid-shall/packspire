# 荷造り画面 実装基準 V1

基準画像: [`packing-equipment-cargo-two-layer-target-v1.png`](packing-equipment-cargo-two-layer-target-v1.png)

この画像は雰囲気案ではなく、1280x720 論理座標へ落とすための構成基準。生成画像内の文字や装備絵を一枚絵として使用せず、各領域を UXML / USS / C# に分けて再構成する。

## 画面構成

| 領域 | 論理座標の目安 | 役割 |
|---|---:|---|
| セーフエリア | `x: 24-1256, y: 20-696` | 全操作要素を収める |
| ヘッダー | `x: 24, y: 20, w: 1232, h: 52` | 戻る、画面名、ルート名 |
| 装備一覧 | `x: 24, y: 84, w: 344, h: 612` | フィルター、4列一覧、並べ替え、所持数 |
| 装備層 | `x: 384, y: 84, w: 524, h: 612` | 保存対象の7x7盤、装備LINK、荷室ポート |
| 専用荷室 | `x: 924, y: 84, w: 332, h: 612` | 配送依頼、荷物、条件判定、出発操作 |
| 列間 | `16px` | 領域を枠で囲まず黒地で分離する |

比率は基準画像の再現より、現行 `PanelSettings` の 1280x720 で操作領域が欠けないことを優先する。7x7盤は正方形を維持し、セルは最低 `54x54` を確保する。

## 挙動契約

- 装備と荷物は同じ収納術式へ置く。
- 装備配置、LINK、色結果は出発時に封印し、遠征中に積む荷物では再計算しない。
- LINKは戦闘カード強化、色は探索術式印、形状は荷室容量を担当する。
- 通常荷物は少ない操作で置ける大きさを基準とする。
- 条件表示は `防護 2/2`、`封印 1/1` のように必要値と供給値を並べる。
- 条件不足時だけ該当行と出発操作を警告状態にする。通常時は再配置を要求しない。
- 大型荷物と呪物だけが例外として追加の配置制約を持つ。
- 標準フローは「依頼選択 -> 前回配置読込 -> 荷物配置 -> 結果封印 -> 出発」とする。

## 表現契約

- 黒曜版画と設定資料集を基調にし、黒地、温かい生成り紙、朱、シアンの順で使う。
- 朱は選択、訂正、確定だけに使う。シアンは有効な接続、達成、登録だけに使う。
- 各装備をカード枠で囲まない。一覧はオブジェクト絵、名前、選択印だけで構成する。
- 紙面は領域背景であり、紙の中に装飾カードを重ねない。
- 線画や書き損じは非操作領域だけに置き、本文より十分に低いコントラストにする。
- 完成カラー絵の主役は配送荷物一つに絞る。装備一覧と装備盤は版画調を基本とする。
- 魔法陣、炉、祭壇、全要素を囲うゴシック枠、光沢の強いモバイル風ボタンは使わない。

## 素材対応

| 要素 | 素材種別 | 方針 |
|---|---|---|
| 黒い外周と版画背景 | 背景 | USS の地色 + 低コントラスト背景画像 |
| 生成り紙3面 | 枠 / 背景 | 伸縮可能な9-sliceを新規用意する。生成画像の切り抜きは使わない |
| 装備絵 | オブジェクト絵 | 既存装備素材を使用。必要なら版画調の派生素材を別途作る |
| 配送荷物 | オブジェクト絵 | 荷物ごとの透過素材を新規作成する |
| LINK線とポート | UI状態 | USSの線と状態別画像。装備位置から動的に描画する |
| 朱の選択印 / シアン登録印 | UI状態 | 共通の小型9-sliceまたはコーナー素材に限定する |
| 背景スケッチ | 背景 | 装備盤ごとの固定装飾。操作要素とは分離する |
| アイコン | アイコン | 既存アイコンセットへ統一し、生成画像中の疑似アイコンは採用しない |

## 実装責務

- **UXML:** ヘッダー、3列、一覧、7x7盤、荷室、条件行、フッター操作の固定構造。
- **USS:** 寸法、余白、紙面、文字、選択、達成、不足、無効、ドラッグ中の見た目。
- **C#:** 装備一覧データ、フィルター、配置、保存、LINK集計、荷物自動搭載、条件判定、出発可否。
- C# から固定座標、固定色、背景画像、装飾用インラインスタイルを設定しない。状態は `is-selected`、`is-satisfied`、`is-shortage`、`is-loaded` などの意味クラスとして USS へ渡す。

## 実装順

1. ヘッダーと3列のシェル。
2. 装備一覧と7x7装備盤。
3. 専用荷室と自動搭載表示。
4. 荷室ポートと条件判定。
5. 背景スケッチ、紙端、朱とシアンの最終調整。

各段階で一領域ずつ確認し、全画面を一度に上書きしない。
