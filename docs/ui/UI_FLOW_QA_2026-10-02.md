# 共通UI・遠征導線の回帰確認

## 確認条件

- Unity Editor の Play Mode。1280×720論理座標、1920×1080実画面。
- 操作は UI Toolkit の PointerDown / PointerUp イベントで実行。
- PlayerPrefs の現行セーブ・staging・backupをEditor SessionStateへ退避し、終了後に元の値へ戻す。確認用の戦利品・遠征回数をユーザーの進行へ残さない。
- バランス測定ではない。通常操作の確認と、確認用状態による終端分岐の検証を区別する。

## 今回の実行結果

| 対象 | 方法 | 結果 |
|---|---|---|
| ホーム→荷造り→遠征準備→出発 | 通常ボタン操作、荷造り保存 | 実RunStateの通常遠征が開始。developer sessionはfalse |
| 戦闘→戦果→移動・次の選択 | 実戦のカード操作、勝利後3番目を選択、3秒待機して受領 | 選択と受領可能状態が維持され、次の区間へ復帰 |
| 敗北→拠点 | 実戦でHP0、終了境界の保存・再開、戻るボタン | 遠征内の敗北表示から直接ホーム。runと再開スナップショットを解放 |
| 第1層祠→続行 | 既存DevShowExpeditionCheckpointで到達状態を準備、通常の続行ボタン | 同じRunState、HP、戦利品を維持。次の候補は第2層 |
| 祠→帰還 | 確認用到達状態、通常の帰還ボタン | 終了理由Return。ホームへ戻り、再開スナップショットを解放 |
| 最深部クリア→拠点 | 第3層終了状態、通常の終了ボタン | 終了理由Clear。ホームへ戻り、再開スナップショットを解放 |
| イベント・休息・探索 | 生成ノードのLocation保存境界から再開し、実際の選択ボタンを操作 | Event/Otherは世界内、Restは全面イベント面。各ノードが一度解決され、awaitingResolution=false |

通常プレイ確認は勝利・戦果受領・次の区間・敗北帰還まで。
一回の通常遠征で最深部まで生存できることは今回の合格条件に含めない。
ボス後の分岐とクリアは状態準備を使った接続検証であり、難度の適正を証明しない。

## 発見して修正した接続・表示

- 通常遠征の終了後に旧GameClear/GameOver画面が重複していた。
  戦利品確定処理は維持し、遠征内の終了表示から直接ホームへ戻す。
  旧結果画面は旧導線用に残す。
- 休息イベントに旧幅440pxと旧アート寸法が残り、全面イベントが縦長に潰れ、ボタンが枠からはみ出していた。
  旧セレクタを除去し、画面固有USSの全面レイアウトへ統一。
  実測は論理座標x=92、y=76、w=1096、h=572。操作ボタン両端がパネル内に収まる。

## 残す課題

- 休息の左イラストは既存の封筒素材のまま。中継所固有の完成イラストではない。
- 祠の図像も既存素材による確認用表現。接近・帰還の操作接続と、完成アートの品質は別に評価する。
- 遠征先の選択理由、勢力のシステム深化、役職のつまみ食い、家宝の成長表現は未決定のまま。新しいルールは追加しない。
- 敵の火力・遠征全体の消耗量と、通常プレイによる最深部到達の難度検証は後続。
